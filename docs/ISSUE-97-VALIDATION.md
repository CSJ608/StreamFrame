# Issue #97 发布前定向验证

2026-10-23，基线 `29d4b92cd2a3dbc12c254ac6554c18a82464d0e2`，Win10 22H2（19045），SDK 10.0.402，现代运行时 10.0.13/8.0.32，本机 .NET Framework 4.8。

## 方法

先 Release build，随后按 net10.0 → net8.0 → net48 顺序执行全套普通测试，共连续十轮；轮间不重启、不清理端口。不启用默认跳过的三个 Soak 场景，本验证与此前三轮 600 秒五目标长测分别计数。

使用独立进程产生受控 CPU 背景负载：进程数为逻辑 CPU 数的一半，每个进程约 80% 工作/20% 休息，缓冲 64KiB；预热 60 秒，贯穿全部测试，结束后回收本次负载进程。没有测量或宣称复刻原报告的精确 CPU 利用率、温度与调度状态。

## 结果

- 30/30 个 TFM-run 成功。
- net10/net8 每轮各 180 项通过，net48 每轮 172 项通过，累计 **5320 项通过，0 失败**。
- Wedge 关键用例 **30/30 通过**，每次包含八轮重连及新会话双向报文验证。
- 每次普通测试的三项 Soak 为正常 Skip，共90次；不计为长测通过。
- 原始逐轮日志、TRX 和 summary 保存在本次本地 `StreamFrame-97-verification` 结果目录。

## 结论与限制

当前实现已包含 Windows 独占监听、接受交接/代次门控、Retry 准入与迟到连接保留。上述定向验证未复现 #97 报告的恢复停滞，结合既有确定性测试及长测结果，没有证据要求本次发布前再修改生产代码。

旧测试的 TCP 握手/旧 Connected 判据不能证明新客户端已被 accept；当前测试验证新会话编号和双向帧，但等待旧会话终止也改变了接入时序。这不是历史现场的唯一因果复现，也不证明所有竞态均已消失。保留 Issue #97 的历史证据及后续观察入口，不将本次通过表述为“历史根因已唯一确认”。
